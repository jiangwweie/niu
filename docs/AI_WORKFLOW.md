# Owner + AI 协作流程

本项目采用 Owner 主导、AI 分工执行的工作方式。

## 1. 总体原则

```text
Owner 负责判断
ChatGPT 负责方案
Codex 负责核心
Claude 负责简单实现和测试
```

AI 不能替代 Owner 做业务规则最终决策。

## 2. 角色分工

### Owner

负责：

- 确认业务需求
- 确认 MVP 范围
- 确认数据模型
- 确认状态流转
- 确认是否进入下一阶段
- 本地运行和验收
- 合并代码

### ChatGPT

负责：

- 分析需求
- 设计方案
- 生成任务卡
- 生成 Prompt
- 审查 Codex / Claude 输出
- 帮 Owner 判断风险和优先级

### Codex

负责：

- 核心后端
- 数据库
- 关键业务规则
- 高风险模块
- 核心测试

### Claude

负责：

- 简单实现
- 前端页面
- 文档
- 测试
- 小范围修复

## 3. 标准工作流

### 3.1 方案阶段

```text
Owner 提出目标
  ↓
ChatGPT 分析方案
  ↓
Owner 判断是否接受
  ↓
生成任务卡
```

### 3.2 核心实现阶段

```text
Owner 将任务卡交给 Codex
  ↓
Codex 检查仓库现状
  ↓
Codex 输出计划
  ↓
Codex 实现
  ↓
Codex 自查
  ↓
Owner / ChatGPT 审查
```

### 3.3 简单实现和测试阶段

```text
Owner 将低风险任务交给 Claude
  ↓
Claude 实现页面/测试/文档
  ↓
Claude 输出变更摘要
  ↓
Owner 本地验收
```

### 3.4 合并阶段

```text
运行测试
  ↓
执行验收清单
  ↓
确认无核心规则破坏
  ↓
合并 dev
  ↓
必要时打 tag
```

## 4. 任务分流规则

### 交给 Codex

- 数据库设计
- migration
- 库存
- 工单状态
- 支付退款
- 结算
- 官方售后
- 财务统计
- 权限模型
- 事务一致性
- 架构重构

### 交给 Claude

- 页面表单
- 页面列表
- 字段展示
- 文案
- 简单 CRUD
- API 测试
- 单元测试
- 文档同步
- mock 数据
- 非核心 bug

### 先问 ChatGPT

- 是否该做
- 如何拆任务
- 是否过度设计
- 风险在哪里
- 验收标准怎么写
- Codex 和 Claude 谁更适合做

## 5. 任务风险分级

### BLOCKER

必须阻塞，不能继续：

- 库存可能对不上
- 支付退款可能对不上
- 结算条件错误
- 财务口径错误
- 数据库结构无法支持核心业务
- 状态机不完整

### HIGH

需要 Codex 处理或复查：

- 核心业务改动
- 数据库改动
- 事务改动
- 权限改动
- 大范围重构

### MEDIUM

可以继续，但需要记录 caveat：

- 普通接口边界不够完善
- 页面体验不完整
- 查询条件暂时简单
- 测试覆盖不足但不影响核心链路

### LOW

不阻塞：

- 文案
- 样式
- 小的交互优化
- 非关键字段展示
- 文档措辞

## 6. 不允许的协作方式

禁止：

```text
让 AI 一口气生成全系统
让 Claude 改库存核心逻辑
让 Codex 擅自扩大 MVP
没有任务卡就做大改
没有验收清单就合并
只看能不能运行，不测业务规则
```

## 7. 推荐节奏

每个模块都按：

```text
设计 → 实现 → 测试 → 验收 → 合并
```

不要多个高风险模块并行推进。
