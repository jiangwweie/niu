# 当前范围说明

## 1. 当前版本目标

当前系统目标是让授权售后门店可以真实使用系统管理：

- 维修工单
- 配件库存
- 支付退款
- 官方售后结算
- 报销台账
- 基础财务报表
- Excel 导出
- 资方台账
- 员工小程序现场作业
- 管理端门店经营管理

当前系统已具备多门店数据隔离能力。门店是业务数据边界；平台超管具备全局管理能力，门店管理员具备本门店管理能力。当前仍不是大型 ERP，也不是微服务系统。

## 2. 当前已落地功能

### 2.1 用户与权限

- 员工账号
- 账号密码登录
- 微信登录与微信绑定
- 角色
- 权限点
- 平台账号 / 门店账号边界
- 多门店数据隔离
- 所有业务表保留 `store_id`

### 2.2 配件与库存

- 官方配件
- 第三方配件
- 第三方配件编码自动生成
- 扫码入库
- 手动入库
- 工单临时新增配件并入库
- 库存查询
- 库存预占
- 库存扣减
- 库存释放
- 库存调整
- 库存流水
- 条形码生成与打印支持

### 2.3 工单

- 创建工单草稿
- 客户姓名和联系方式
- 车型
- 车架号
- 电池号
- 维修项目
- 使用配件
- 人工费
- 其他费用
- 官方售后订单号
- 备注
- 状态流转：`DRAFT` → `REPAIRING` → `REPAIR_DONE` → `DELIVERED`
- 草稿删除
- 取消工单
- 标记维修完成
- 交付关闭
- 维修历史按车架号查询

### 2.4 支付与退款

- 多次付款
- 混合付款
- 微信、支付宝、银联等支付方式
- 退款记录
- 定金退款必须有记录
- 实收金额达到应收金额，或标记无需收款后，才允许交付关闭
- 支付和退款不自动改变工单状态

### 2.5 官方售后

- 手动录入官方结算金额
- 标记官方结算
- 记录官方售后订单号
- 客户支付和官方结算分开统计

### 2.6 报销台账

- 员工提交报销
- 报销用途
- 报销金额
- 备注
- 待确认、已确认、已驳回/取消
- 老板确认后计入运营成本

### 2.7 财务报表

- 配件收入
- 人工费
- 其他收入
- 官方结算收入
- 配件成本
- 报销成本
- 利润
- 日报
- 月报
- 时间范围查询
- Excel 导出

### 2.8 资方台账

- 资方申请资料
- 资方合同
- 分期计划
- 资方收款登记
- 资方台账导入导出
- 变更日志

## 3. 新增规划功能

### 3.1 客户侧预约排号系统

客户侧预约排号已进入规划，但必须作为独立业务边界设计：

- 客户预约到店
- 选择服务类型：看车、维修、售后、检测
- 到店签到
- 排队取号
- 客户查看预约和服务进度
- 员工端查看今日队列、叫号、过号、接待
- 员工确认后把预约转成工单草稿

客户侧预约不能直接触发：

- 库存预占
- 库存扣减
- 支付记录
- 退款记录
- 工单交付关闭
- 官方结算
- 财务入账

## 4. 当前仍不做

- 自动采购
- 自动同步官方系统
- 自动打款
- 复杂连锁/区域运营
- 跨门店自动调拨或自动结算
- 员工提成
- 客户签字
- 图片上传
- 多门店汇总报表
- 复杂审批流
- 凭证上传
- 报销类型管理
- 复杂盘点流程
- 复杂 BI
- 微服务
- MQ
- Redis

## 5. 扩展预留

可以预留，但不实现：

- `store_id`
- 审批流状态
- 报销凭证字段
- 多门店字段
- 官方系统单号
- 字典配置
- 角色权限扩展
- 客户侧 `client_user`
- 预约单 `service_appointment`
- 预约容量规则 `appointment_capacity_rule`

## 6. 范围控制原则

任何新需求必须先回答：

```text
1. 是否属于当前阶段？
2. 是否影响库存/支付/财务核心链路？
3. 是否可以先用手工方式解决？
4. 是否会导致数据库模型大改？
5. 是否会延迟主链路跑通？
```

如果答案不清楚，先不做。
