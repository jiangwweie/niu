## 4. 库存任务示例

```markdown
# Codex 任务：实现库存入库与库存流水

## 业务目标

支持官方配件和第三方配件入库。每次入库必须增加库存，并生成库存流水。

## 涉及模块

- inventory
- part

## 涉及表

- part
- inventory_stock
- inventory_flow

## 业务规则

1. 官方配件可手动输入官方品号
2. 第三方配件编码由系统生成
3. 入库必须记录数量、成本价、操作人、时间
4. 每次库存变化必须生成 inventory_flow
5. 不允许直接修改库存而不生成流水

## 不做范围

1. 暂不做复杂盘点
2. 暂不做自动采购
3. 暂不做多门店调拨

## 验收标准

1. 新配件入库后库存增加
2. 老配件再次入库后库存累加
3. 每次入库都能查到库存流水
4. 第三方配件能自动生成编码
```

## 5. 支付任务示例

```markdown
# Codex 任务：实现支付记录、退款记录与结算判断

## 业务目标

支持一个工单多次付款、混合付款和退款。工单已结算必须根据实收金额判断。

## 涉及模块

- workorder
- payment

## 涉及表

- work_order
- payment_record
- refund_record

## 业务规则

1. 一个工单允许多次付款
2. 一个工单允许混合付款
3. 退款必须生成退款记录
4. 实收金额 = 支付总额 - 退款总额
5. 实收金额 >= 应收金额 才允许已结算

## 不做范围

1. 不对接真实支付网关
2. 不做自动退款
3. 不做自动打款

## 验收标准

1. 多次付款能正确累计
2. 混合付款能正确展示
3. 退款后实收金额减少
4. 实收不足不能结算
5. 实收达到应收可以结算
```
