# M19B admin-web 真实试用防呆修复 Smoke

## 修复问题清单、原因与方案

- 菜单权限：移除系统设置 `|| true`，工单、配件、导出等菜单按现有权限显示。
- 按钮权限：员工新增/编辑/重置密码/停启用、门店保存、配件新增/编辑/删除/停启用等按钮按权限显示。
- 登录旧 token：登录接口保持不带 Authorization，`/api/auth/me` 和业务接口继续带 Authorization。
- 配件删除：后端返回 `canDelete`，有库存、库存流水或工单引用时前端不显示可直接删除动作，引导使用停用。
- 库存调整/入库：提交前增加二次确认，提示配件、数量、原因/成本以及会生成库存流水。
- 报销确认：确认前二次确认，说明会计入运营成本。
- 官方结算：标记已结算、无需结算前二次确认，说明影响官方结算状态和财务统计。
- 人员展示：报销、支付、退款响应补充姓名字段，前端优先展示姓名，缺失时显示“员工 #ID”。
- 金额/字段展示：客户/车辆维修历史使用 MoneyText；工单成本金额 0 显示 ¥0.00；官方结算时间格式化到分钟；配件来源大小写兼容。

## 不改变的业务规则

- 不改变库存 RESERVE / RELEASE / CONSUME 语义。
- 不改变支付、退款、结算、官方结算、报销确认的后端校验和财务口径。
- 报销仍只有确认后计入运营成本。
- 官方结算与客户支付仍分开统计。
- 配件有业务记录时不删除业务流水。

## 测试结果

- 后端：使用 Java 17 执行 `mvn -f backend/pom.xml test` 通过，703 个测试无失败。
- admin-web：`npm --prefix admin-web run lint` 通过；`npm --prefix admin-web run build` 通过。
- 小程序：`cd mini-program && npx tsc --noEmit` 仍失败，失败项为历史 miniprogram/dom 与 tdesign 类型问题。

## 手工 Smoke 步骤

1. 浏览器保留旧 token 时登录，确认登录请求不带 Authorization 且不再因旧 token 401。
2. 调用 `/api/auth/me`，确认仍带 Authorization。
3. 无权限用户不显示系统设置空菜单和无权限按钮。
4. 库存调整弹出二次确认，取消不提交。
5. 入库弹出二次确认，取消不提交。
6. 有库存/流水/工单引用的配件不显示可直接删除动作。
7. 报销列表和详情显示报销人姓名或“员工 #ID”。
8. 支付/退款详情显示操作人、收款人姓名或“员工 #ID”。
9. 报销确认弹出二次确认。
10. 官方标记已结算/无需结算弹出二次确认。
11. 金额显示不出现 MoneyText NaN，0 成本显示 ¥0.00。
12. 401 / 403 行为保持。

- 官方结算已结算后是否允许修改。
- 报销已确认后是否允许撤销。
- 客户 / 车辆是否从“删除”统一改成“停用 / 隐藏”。
- 库存详情页 / 配件详情页是否新建完整详情页。
- 是否引入后端统一 action availability。
- 小程序页面是否重命名 placeholder。
- 小程序重复代码是否抽组件。
- 扫码选件入口是否进一步降级。
