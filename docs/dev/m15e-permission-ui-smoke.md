# M15E 权限体验层 Smoke Test 报告

## 环境配置
- **端**: admin-web & mini-program
- **运行模式**: real

## 核心原则与测试声明
本次所有涉及的权限判断**仅**在前端作为体验优化（如菜单显隐、按钮置灰及拦截等），所有接口请求的最终通过或拦截**始终**由后端 `@PreAuthorize` 保证。即使前端强行绕过，无权限接口调用仍将收到后端的 403 返回。

## 1. 验证目标及边界

### 已实现：
1. **admin-web**：基于 `hasPermission(code)` 动态显示/隐藏：财务报表菜单项，导出 Excel，官方结算管理等按钮及页面内操作入口。
2. **mini-program**：基于 `hasPermission(code)` 动态控制工作台入口，例如配件入库、新建工单、取消工单、记录支付与退款等高风险操作按钮。
3. **403 异常处理**：若直接调用无权限接口，所有端捕获 403 状态码并在页面仅抛出提示 "无权限访问该资源" (Toast/ElMessage)，**不再强制登出或清理 token**。

### 明确未做内容：
1. **完整 RBAC 管理后台**：未创建角色、权限点的增删改查前端页面。
2. **账号管理系统**：仍无用户类型 (`user_type`、`account_type`) 的详细管理界面。
3. **Refresh Token**：只依赖于现有的 `accessToken` 失效跳 401。
4. **复杂动态菜单/路由**：`router` 结构未改，仅通过布局侧边栏直接 `v-if` 或过滤渲染来实现隐藏。未配置类似动态生成 Vue Router tree 的架构。

所有前后端鉴权联通顺畅，权限控制实现了体验与安全解耦，M15E 里程碑顺利达成。
