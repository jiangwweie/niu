# M26C-2 前端交互健壮性与错误透明度修复验收

## 修复范围

本次修复覆盖了 P0 体验审计遗留的 10 个确认问题，严格遵守不修改核心业务规则、不修改后端及数据库的原则。

### 1. 管理端：组件交互冲突修复
- **配件列表删除重叠冲突**：修复 `parts/index.vue` 中 `showDeleteCheck` 弹窗与确认删除二次弹窗重叠问题。现仅当不可删除时才显示检查弹窗，可删除时直接提示确认删除。
- **草稿删除 Promise 未捕获**：修复 `work-order/index.vue` 中 `handleDeleteDraft` 未捕获用户取消导致 Console 抛错及潜在挂起问题。

### 2. 管理端/小程序：错误吞噬问题修复
- **删除配件接口失败吞噬**：修复 `parts/index.vue` 中 `deletePart` 后端返回 400（已被使用等原因）时不展示错误信息的问题。
- **全局 Request 拦截器丢失元数据**：修复 `admin-web/src/utils/request.ts` 中拦截器直接抛出 Error 导致 AxiosError 原始数据丢失的问题，从而保证类似清理试运行数据页面能够正确捕获错误。

### 3. 全局：状态映射与透明化
- **全局清理旧状态文案**：根据决策，移除了所有前端对旧状态（如 PENDING_ACCEPT, SETTLED 等）的遗留展示逻辑，彻底清除了用户可见文案中的“旧状态，请先清理试运行数据”字样。
- **管理端结算状态透明化**：修改 `getProgressStatusText` 对未知状态不再返回 `-`，而是返回 `未知状态（CODE）`。同时涉及 `getCashierStatusText` 和 `getInventoryStatusText`。
- **管理端无需收款原因透明化**：修复模板中的 fallback 覆盖，未知原因展示 `其他（CODE）`。
- **管理端收银报表支付方式透明化**：未知支付方式由展示“其他”修改为展示 `其他（CODE）`。
- **清理工具文案更新**：将 `trial-data/index.vue` 中的“清理旧状态工单”统一更名为“未兼容版本数据”，避免歧义。

### 4. 其它修复
- **空值适配**：修复 `inventory.ts` 中 `adaptFlow` 错用 `||` 的问题，改用 `??` 以确保正常的 `operatedAt` 空字段回退到 `createdAt`。
- **时间精度丢失**：修复 `formatDateTime` 将后端返回的高精度时间强制截断到分钟的问题，现保留并展示到秒：`YYYY-MM-DD HH:mm:ss`。

## 验证结论

- **范围约束**：所有修复均局限于 `admin-web` 和 `mini-program` 前端代码逻辑。
- **规则约束**：核心财务、库存及状态机规则零改动。
- **环境安全**：无任何密码、Token 泄漏，未涉及任何生产数据库和后端重启操作。
- **编译检查**：
  - `admin-web` 静态类型检查及生产构建均通过。
  - `mini-program` 类型检查通过（除去不可控的外部库报错），可正常发行体验版。
