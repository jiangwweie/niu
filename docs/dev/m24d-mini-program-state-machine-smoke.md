# M24D 小程序工单状态机适配 Smoke 文档

## 1. 状态展示检查

### 1.1 工单进度状态

| 值 | 展示文案 | 标签颜色 |
|---|---|---|
| DRAFT | 新建中 | 蓝色 |
| REPAIRING | 维修中 | 橙色 |
| REPAIR_DONE | 维修完成 | 绿色 |
| DELIVERED | 已交付 | 绿色 |
| CANCELLED | 已取消 | 灰色 |

旧状态（PENDING_ACCEPT / ACCEPTED / PART_ORDERED / PART_ARRIVED / SETTLED）显示为"旧状态，请先清理试运行数据"（红色）。

### 1.2 收银状态

| 值 | 展示文案 | 标签颜色 |
|---|---|---|
| NO_CHARGE | 无需收款 | 蓝色 |
| UNPAID | 未收款 | 橙色 |
| PARTIAL_PAID | 部分收款 | 橙色 |
| PAID | 已收齐 | 绿色 |
| REFUND_PENDING | 待退款 | 红色 |
| PARTIAL_REFUNDED | 部分退款 | 红色 |
| REFUNDED | 已退清 | 灰色 |

### 1.3 库存状态

| 值 | 展示文案 | 标签颜色 |
|---|---|---|
| NOT_RESERVED | 未预占 | 灰色 |
| RESERVED | 已预占 | 橙色 |
| CONSUMED | 已扣减 | 绿色 |
| RELEASED | 已释放 | 灰色 |

## 2. 工单列表检查

- [ ] 列表筛选 tabs 使用：全部 / 维修中 / 维修完成 / 已交付 / 已取消
- [ ] 不再显示旧工单状态文案，旧状态统一显示"旧状态，请先清理试运行数据"
- [ ] 每张卡片显示进度状态 tag
- [ ] 每张卡片显示收银状态 tag
- [ ] 金额行显示：应收、净实收、待收（橙色）
- [ ] 旧状态工单显示"旧状态，请先清理试运行数据"

## 3. 工单详情检查

- [ ] 顶部显示进度状态 tag
- [ ] 顶部显示收银状态 tag
- [ ] 顶部显示库存状态 tag
- [ ] 基础信息区域显示无需收款原因（如“无需收款”工单）
- [ ] 收银信息区域显示：应收金额、净实收、待收金额（橙色）、可退金额（如有）
- [ ] 旧状态工单显示"旧状态，请先清理试运行数据"

### 3.1 下一步提示

| 场景 | 提示文案 |
|---|---|
| 新建中 | 请完善信息后提交工单。 |
| 维修中 + 未收款 | 维修中，库存已预占，可记录定金或继续维修。 |
| 维修中 + 部分收款 | 维修中，已收到部分款项，可继续维修。 |
| 维修完成 + 部分收款/未收款 | 车辆已维修完成，请先收齐尾款后再交付关闭。 |
| 维修完成 + 已收齐 | 维修完成且款项已收齐，可以交付关闭。 |
| 维修完成 + 无需收款 | 无需收款，可以交付关闭。 |
| 已交付 | 工单已交付关闭。 |
| 已取消 + 待退款 | 工单已取消，请处理客户退款。 |
| 已取消 | 工单已取消。 |

## 4. 标记维修完成检查

- [ ] 仅 canMarkRepairDone=true 时显示按钮
- [ ] 点击弹出二次确认
- [ ] 提示文案："标记维修完成后，工单配件库存将正式扣减，不能再普通取消工单。"
- [ ] 应收为 0 时：显示无需收款原因选择（官方售后/免费检测/老板免单/质保处理/其他）
- [ ] 应收为 0 时：原因必填，不允许空原因提交
- [ ] 成功后刷新详情，状态显示“维修完成”
- [ ] 库存状态显示已扣减

## 5. 交付关闭检查

- [ ] 仅 canDeliver=true 时显示按钮
- [ ] 点击弹出二次确认
- [ ] 展示工单进度、收银状态、应收金额、净实收、待收金额
- [ ] 已收齐场景文案："工单已结清。确认交付关闭后，工单将进入已交付状态；库存已在标记维修完成时扣减，本操作不再改变库存。"
- [ ] 无需收款场景文案含无需收款原因
- [ ] 严禁出现"交付关闭后库存将正式扣减"、"交付时扣库存"、"强制交付"等文案
- [ ] 成功后刷新详情

## 6. 收款/退款检查

### 收款
- [ ] 仅 canRecordPayment=true 时显示
- [ ] 金额必须 > 0
- [ ] 金额不能超过待收金额
- [ ] 收款方式必填
- [ ] 收款不改变工单进度状态
- [ ] 弹窗提示"收款不改变工单进度状态"

### 退款
- [ ] 仅 canRecordRefund=true 时显示
- [ ] 金额必须 > 0
- [ ] 金额不能超过可退金额（refundableAmount）
- [ ] 退款方式必填
- [ ] 退款原因必填
- [ ] 退款不改变工单进度状态
- [ ] 小程序不显示已交付后退款入口

## 7. 取消工单检查

- [ ] 仅 canCancel=true 时显示
- [ ] 文案："取消工单将关闭此工单；如已预占库存，系统将自动释放。若已有收款，请后续处理退款。"
- [ ] 取消原因必填
- [ ] 成功后刷新详情

## 8. 提交工单后状态检查

- [ ] 提交工单后状态显示“维修中”
- [ ] 库存状态显示“已预占”
- [ ] 提交对话框文案："提交后进入维修中，并预占相关库存。"
- [ ] 不再出现旧版提交后状态文案

## 9. 追加非库存费用

本轮小程序暂不开放"追加非库存费用"入口。

REPAIR_DONE 后追加非库存费用已由后端和 admin-web 支持，小程序本轮暂不开放入口。

## 10. 本轮不做事项

- 小程序不开放已交付后退款入口
- 小程序不开放追加非库存费用
- 不修改后端接口
- 不修改 admin-web
- 不修改数据库

## 12. 人工验收步骤

1. 使用有工单数据的账号登录小程序
2. 进入工单列表页，确认状态 tabs 和标签正确
3. 点击维修中的工单，确认详情页显示三个状态标签和收银信息
4. 测试"标记维修完成"流程（含应收为 0 的无需收款原因选择）
5. 测试"交付关闭"流程
6. 测试"记录收款"流程
7. 测试"记录退款"流程
8. 测试"取消工单"流程
9. 创建新工单，测试提交流程
10. 确认已交付和已取消状态下页面为只读
11. 确认小程序不显示交付后退款入口
12. 如有旧状态工单，确认显示"旧状态，请先清理试运行数据"
