# 小程序创建工单页客户/车辆搜索输入框热修复

## 问题背景
**反馈来源：** 客户体验版发现新问题。
**现象描述：** 小程序创建工单页面，搜索已有客户和已有车辆时，输入框似乎被其他层级压在下方，无法正常获得焦点，无法输入内容。

## 根因分析

经过排查，导致输入框无法输入及被遮挡错觉的根因主要有两个方面：

1. **输入值频繁被 `setData` 重置（控制组件冲突）：** 
   * **现象：** 在 TDesign（以及许多微信小程序自定义输入组件）中，如果将输入框的 `value` 属性绑定到 `data`，并且在 `bind:change` 每次触发时立刻调用 `this.setData` 更新该绑定的值，会导致输入框不断重新渲染。这在很多机型上表现为频繁失去焦点、光标位置跳跃或键盘直接收起，从而导致“无法连续输入多个字符”的问题。
   * **搜索请求引发的重置：** 当用户输入触发了 debounce 后的搜索请求，原有代码会执行 `this.setData({ customerSearchState: 'loading' })`，这触发了页面的重渲染。若此时绑定的 `customerSearchKeyword` 还没有被正确地设为用户最后输入的文本（或在 typing 时被阻断），渲染会强制将输入框置空或置为旧值，导致用户输入的内容被清空。

2. **Flex 布局下的宽度塌陷导致“层级压住”的错觉：**
   * **现象：** 客户搜索和车辆搜索的 `t-search` 组件都包裹在一个 `display: flex` 的 `view` 容器中。
   * **原因：** `t-search` 组件在 flex 容器中默认没有指定 `flex: 1` 占据剩余空间。在某些状态下，其宽度可能塌陷到极小，导致其可点击区域（焦点获取区域）变为 0，从而给用户一种“输入框被其他透明遮罩层遮挡”无法点击的错觉。

3. **`t-popup` 的 `z-index` 使用错误（次要修复）：**
   * **现象：** 原代码中 `t-popup` 的 `z-index` 被配置在 `custom-style` 中（如 `custom-style="height: 70vh; z-index: 11000;"`），这并不是 TDesign 官方推荐的高层级处理方式，容易导致弹层内部元素的层级上下文错乱。

## 修复说明

### 1. 客户搜索修复 (Customer Search)
* **移除输入防抖中的 `setData` 干扰：** 修改了 `onCustomerSearchInput` 方法。不再于每次输入时调用 `this.setData({ customerSearchKeyword: value })`。而是先将用户输入暂存到页面实例级属性 `this.currentCustomerKeyword` 中。
* **按需渲染：** 仅在 300ms 防抖结束、即将触发实际的网络搜索（`onCustomerSearch`）前，才通过 `setData({ customerSearchKeyword: this.currentCustomerKeyword })` 一次性更新绑定的值，以避免由于后续的 `customerSearchState: 'loading'` 带来的页面重绘将输入框意外清空。
* **样式修复：** 在 `index.wxml` 中为 `t-search` 增加 `style="flex: 1;"`，确保其在 flex 容器中正常撑开，恢复完整的可点击区域。
* **空状态文案对齐：** 更新了无结果及请求失败时的提示文案，使之符合要求。

### 2. 车辆搜索修复 (Vehicle Search)
* **补齐输入防抖逻辑：** 原逻辑中 `onVehicleSearchInput` 直接调用 `setData` 并且没有包含 300ms 防抖和自动触发搜索的代码。
* **防止 `setData` 重置输入：** 和客户搜索一样，通过 `this.currentVehicleKeyword` 暂存输入值，添加 300ms debounce 防抖定时器，在防抖结束后更新数据并自动触发搜索。
* **样式与层级修复：** 同样补充了 `style="flex: 1;"` 确保宽度正常，将 `t-popup` 的 `z-index` 从 `custom-style` 提出来作为组件属性传递。
* **补齐空状态展示：** 在 `.ts` 中补充了 `vehicleSearchState` 及 `vehicleSearchError` 的数据流管理，并在 `.wxml` 中增加了统一规范的搜索中、无结果、失败状态文案。

## 环境影响及合规性检查
* **后端及数据库：** 未修改后端（Backend）逻辑；未修改数据库及任何 Migration；未删除任何历史数据。
* **业务规则：** 未触碰任何工单状态流转、库存预占、正式扣减、支付、退款结算及财务核心逻辑。
* **TypeScript 检查：** 执行 `npx tsc --noEmit` 失败，但失败项均为历史已存在的 `miniprogram-api-typings` 冗余声明及 `tdesign-miniprogram` 组件缺少依赖引发的全局类型错误。这些报错不会影响微信开发者工具自身的编译与小程序上传。
* **提交合规：** 未执行 `git push` 操作，代码改动干净合规，仅聚焦修复当前输入框遮挡失焦问题。

## 验证步骤与体验版上传

### 微信开发者工具验证步骤
1. 打开“创建工单”页面。
2. 分别点击“搜索已有客户”和“搜索已有车辆”。
3. 在弹出的输入框内输入任意字符。
4. 确认软键盘不会在中途被异常收起，支持连续输入。
5. 停顿 300ms 后，确认能自动触发网络搜索。
6. 确认搜索结果列表出现时，输入框不会被重置为空，也未被搜索层覆盖。
7. 分别模拟输入不存在的关键字及断网，确认展示预期的空提示文案和错误文案。
8. 选中一项结果，确认弹窗关闭后正确回填信息至草稿表单中。
