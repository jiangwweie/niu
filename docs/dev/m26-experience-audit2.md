## 5. P0 问题清单

> [!IMPORTANT]
> **P0 定义**：阻塞客户使用 / 误导业务判断 / 可能导致错误库存或财务数据 / 可能造成数据不可追溯。

### P0-01 工作台「待办与提醒」永远显示静态空状态
- **编号**：P0-01
- **模块**：小程序
- **页面**：`pages/dashboard/`
- **问题描述**：「待办与提醒」区域为硬编码静态内容，永远显示「当前无待办工单」，不加载任何真实数据。
- **用户影响**：员工打开小程序首页看到「无待办」，误以为当前没有需要处理的工单，可能导致工单遗漏、车辆交付延迟。
- **严重级别**：P0
- **涉及文件**：[index.wxml](file:///Users/jiangwei/Documents/niu/mini-program/src/pages/dashboard/index.wxml)
- **是否需要 backend**：是（需要后端提供统计接口，或获取当前门店待处理工单数量）
- **是否涉及数据风险**：否
- **建议修复方式**：对接真实工单数据，展示待维修/待交付等真实待办数量；或在没有接口支持前，整体移除该硬编码区域，避免误导。
- **验证方式**：有 DRAFT 或 REPAIRING 工单时，首页应显示对应的待办工单数量。

### P0-02 小程序退出登录无二次确认
- **编号**：P0-02
- **模块**：小程序
- **页面**：`pages/mine/`
- **问题描述**：退出登录按钮点击后直接清除本地 Token 和登录态并跳转回登录页，没有任何 `wx.showModal` 提示二次确认。
- **用户影响**：用户极易发生误触，误触后必须重新输入账号、密码并重新加载图片验证码，在移动端和外勤现场极度耗时且体验差。
- **严重级别**：P0
- **涉及文件**：[index.ts](file:///Users/jiangwei/Documents/niu/mini-program/src/pages/mine/index.ts)
- **是否需要 backend**：否
- **是否涉及数据风险**：否
- **建议修复方式**：添加 `wx.showModal` 确认，文案示例：「确定退出登录？退出后需重新输入账号密码」
- **验证方式**：点击「退出登录」按钮，弹出系统提示框，选择“取消”不产生任何动作，选择“确定”才执行退出。

### P0-03 clearAuth 存储键不匹配（可能残留旧用户数据）
- **编号**：P0-03
- **模块**：小程序
- **页面**：全局（`stores/auth.ts`）
- **问题描述**：`clearAuth()` 执行 `wx.removeStorageSync('user')`，但 `storage.setUser()` 写入的键是 `auth_user`。两者不匹配，导致退出后 `auth_user` 中的旧用户数据可能未被清除。
- **用户影响**：多个员工交替登录小程序或重新登录时，可能在页面重新拉取 `/me` 前短暂显示上一个用户的姓名、门店等信息，有数据隐私及越权展现风险。
- **严重级别**：P0
- **涉及文件**：[auth.ts](file:///Users/jiangwei/Documents/niu/mini-program/src/stores/auth.ts)、[storage.ts](file:///Users/jiangwei/Documents/niu/mini-program/src/utils/storage.ts)
- **是否需要 backend**：否
- **是否涉及数据风险**：是（用户身份及敏感信息残留）
- **建议修复方式**：将 `auth.ts` 中的 `wx.removeStorageSync('user')` 改为 `wx.removeStorageSync('auth_user')`（或直接调用封装好的 `storage.clearUser()`）。
- **验证方式**：退出登录后在开发者工具 Storage 面板检查 `auth_user` 的值是否已被清空。

### P0-04 管理端工单详情页「查看」导航链接断裂
- **编号**：P0-04
- **模块**：管理端
- **页面**：`views/customer/index.vue`、`views/vehicle/index.vue`
- **问题描述**：客户详情和车辆详情中的「维修历史」表格，点击「查看」跳转 `/work-order?id=xxx`，但工单页面在 `onMounted` 里只读取了 `route.query.partId`，没有去提取和过滤 `id`，导致跳转到工单列表页后无法筛选或自动展开该工单。
- **用户影响**：从客户/车辆详情点击查看工单，无法看到对应工单的细节，相当于链接失效。
- **严重级别**：P0
- **涉及文件**：[customer/index.vue](file:///Users/jiangwei/Documents/niu/admin-web/src/views/customer/index.vue)、[vehicle/index.vue](file:///Users/jiangwei/Documents/niu/admin-web/src/views/vehicle/index.vue)、[work-order/index.vue](file:///Users/jiangwei/Documents/niu/admin-web/src/views/work-order/index.vue)

- **是否涉及数据风险**：否
- **建议修复方式**：在 `work-order/index.vue` 的 `onMounted` 里解析 `route.query.id`，并在获取数据后默认触发显示该工单的抽屉/弹窗。
- **验证方式**：在客户详情页的维修历史中点击「查看」，确认能正确跳转到工单页并自动拉起该工单的详情抽屉。
