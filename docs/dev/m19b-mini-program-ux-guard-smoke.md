# M19B 小程序真实试用防呆修复 Smoke

## 修复问题清单、原因与方案

- 请求错误提示：原先部分非 2xx 错误优先显示通用文案。已改为后端 `message` 优先，401/403 行为保持不变。
- 客户搜索：原先主要依赖键盘提交。已增加 300ms 输入防抖、显式搜索按钮，并区分未搜索、搜索中、无结果、失败。
- PART 手输：原先 PART 可输入项目名但无 `partId`。已将 PART 项目名改为选择/扫码/临时新增带出，手工项目引导使用工时或其他费用。
- 配件库存前置校验：原先选择/扫码命中主数据后未检查库存。已展示可用/实际/预占或暂无库存记录，并在无库存、可用为 0、数量超过可用时禁止普通 PART 保存。
- 收款入口：原先已收齐仍可能显示。已按状态和待收金额隐藏收款入口，已收齐显示提示，并限制收款金额不超过待收。
- 退款入口：DRAFT 隐藏，CANCELLED、DELIVERED 保留入口，退款上限使用 `refundableAmount`。
- 标记维修完成：调用始终发送 `{}`，后端也兼容空 body。
- 登录守卫：补齐入库、配件、报销、创建工单等业务页 onShow 登录检查。
- 入库页新增配件：移除无提示 disabled，改为明确提示去配件管理新增或使用工单临时新增。

## 不改变的业务规则

- DRAFT 不预占库存；提交后才 RESERVE；维修完成后才 CONSUME。
- 普通 PART 必须关联真实 `partId`。
- 临时新增配件仍走创建主数据、入库、生成 INBOUND、加入工单。
- 支付只生成 payment_record，不自动结算。
- 退款只生成 refund_record，不反结算、不回滚库存、不改变工单状态。

## 测试结果

- 后端：使用 Java 17 执行 `mvn -f backend/pom.xml test` 通过，703 个测试无失败。
- admin-web：`npm --prefix admin-web run lint` 通过；`npm --prefix admin-web run build` 通过。
- 小程序：`cd mini-program && npx tsc --noEmit` 仍失败，失败项为历史 miniprogram/dom 重复类型、tdesign-miniprogram 类型缺失；本次新增的业务类型错误已修复。

## 手工 Smoke 步骤

1. 输入客户姓名/手机号，确认自动搜索和显式搜索按钮都可用。
2. 搜索无结果时显示“未找到客户，可直接填写新客户信息”。
3. 添加 PART 时尝试手输项目名，应提示必须从配件库选择。
4. LABOR / OTHER 手输项目名可保存。
5. 选择或扫码无库存配件，应显示库存状态并禁止普通 PART 保存。
6. 选择有可用库存配件，数量不超过可用时可加入草稿。
7. DRAFT 不显示收款、退款、结算、维修完成。
8. 已收齐不显示记录收款，显示“已收齐”。
9. 收款金额超过待收金额时前端拦截。
10. CANCELLED / DELIVERED 保留记录退款入口，最终以后端校验为准。
11. 标记维修完成空 body 不再失败。
12. 后端 400 message 能展示业务提示。
13. 入库、报销、配件页未登录跳登录。
14. 401 / 403 行为保持。
