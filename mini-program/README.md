# 小牛电动官方授权店两轮车维修售后库存管理系统 - 员工小程序

## 1. 技术栈与阶段目标

- **阶段**：员工小程序生产验收阶段
- **技术栈**：原生微信小程序 + TypeScript + TDesign Miniprogram
- **目标**：支撑门店员工现场作业，包括工单草稿、配件库存、入库、收银、退款、维修完成、交付关闭、报销和资方业务。

### 重要边界

- 员工小程序只调用 `/api/staff/**` 和 `/api/auth/**`。
- 工单提交、维修完成、交付关闭、支付、退款、报销等写操作必须走后端 Service 校验。
- 客户预约排号不在本小程序内承载，后续建议独立客户小程序和 `/api/client/**`。
- 不展示成本价及与成本相关的任何敏感字段。
- 不在前端伪造工单状态、库存状态、支付退款状态或财务结果。

## 2. API 层与 Mock / Real 模式说明

- **API 方法位置**：所有请求定义在 `src/api/` 目录下。
- **路径规范**：员工端业务 API 对齐后端 `/api/staff/**`，登录与微信绑定走 `/api/auth/**`。
- **运行模式**：
  - 当前默认配置为 `API_MODE = 'real'`。
  - `mock` 模式仅用于本地演示和断点调试。

## 3. 页面功能说明

当前页面采用大按钮、卡片化布局，适合员工现场操作：

1. **工作台 (`pages/dashboard`)**：展示待处理入口和常用操作。
2. **工单查询 (`pages/work-orders`)**：展示工单列表，支持搜索和状态筛选。
3. **工单详情 (`pages/work-order-detail`)**：展示工单状态、客户车辆、费用明细、收款退款、维修完成和交付关闭操作。
4. **新建工单 (`pages/create-work-order`)**：支持工单草稿、费用明细、配件费、工时费和其他费用。
5. **配件查询 (`pages/parts`)**：展示配件编码、配件名称、来源标签、官方品号、型号与分类。
6. **库存查询 (`pages/inventory`)**：展示配件实际库存、可用库存、预占库存及最近变更时间。
7. **配件入库 (`pages/inbound`)**：支持已有配件入库和创建配件并入库。
8. **收银工作台 (`pages/cashier-workbench`)**：聚焦待收款、待交付关闭等现场收银动作。
9. **报销 (`pages/reimbursement`)**：员工提交报销申请。
10. **资方业务 (`pages/funding`)**：资方申请、台账、收款登记等门店现场能力。
11. **我的 (`pages/mine`)**：账号信息、微信绑定、环境配置和退出登录。

## 4. 安全与字段边界

- 员工端不展示 `referenceCostPrice`、`costPriceSnapshot`、`lineCostAmount` 等敏感成本字段。
- 支付和退款只记录资金明细，不自动改变工单状态。
- 官方结算和客户支付分开统计。
- 资方业务不替代客户支付、退款和官方售后结算。
- 客户侧预约排号后续必须使用独立客户身份，不得复用员工登录态。

## 5. TDesign 运行说明

1. 确保已经在目录内执行 `npm install`。
2. 打开微信开发者工具并导入本项目。
3. 点击菜单栏 **工具 -> 构建 npm** 确保 TDesign 组件生效。
4. 编译预览页面。

## 6. Staff 接口联调说明

1. **默认模式**：当前项目的 API 请求默认处于 `API_MODE = 'real'`。
2. **切换模式**：如需使用本地 mock，请打开 `src/utils/config.ts`，将 `API_MODE` 修改为 `'mock'`。
3. **BASE_URL 配置**：
   - 在 `config.ts` 中配置 `BASE_URL`。本地可填 `http://localhost:8080`。
   - 真机无法访问电脑的 localhost。真机联调必须配置为局域网 IP，或者使用内网穿透与 HTTPS 域名。
4. **微信开发者工具设置**：
   - 本地调试 HTTP 服务时，可在工具右上角 **详情 -> 本地设置** 中勾选 **不校验合法域名、web-view（业务域名）、TLS版本以及HTTPS证书**。
5. **dev-only Header 的用途**：
   - dev/test 联调时，请求可带 `X-User-Id` 和 `X-Store-Id` Header 供后端识别。此方案仅用于联调。
6. **当前联调边界**：
   - 支持工单草稿、提交、取消、维修完成、交付关闭、收款、退款、入库、报销和资方业务。
   - 客户预约排号不属于员工小程序当前边界。
   - 客户侧后续应独立小程序，使用 `/api/client/**`。

## 7. 核心业务边界

- `DRAFT` 草稿添加费用明细不触发库存预占。
- `submit` 后进入 `REPAIRING`，后端触发库存预占。
- `mark-repair-done` 后进入 `REPAIR_DONE`，后端正式扣减库存。
- `deliver` 后进入 `DELIVERED`，只完成交付关闭，不重复扣库存。
- `cancel` 释放已预占库存。
- 支付和退款只记录资金明细，不自动改变工单状态。
- 官方结算和客户支付分开统计。
