# 小牛电动官方授权店两轮车维修售后库存管理系统 - 管理端 (admin-web)

本系统是“小牛电动官方授权店”的内部管理系统前端（admin-web）。当前版本为 Mock UI 阶段，用于展示系统架构、核心页面结构、基本交互流程以及前端组件能力。

## 技术栈

*   **框架**: Vue 3 + Vite
*   **路由**: Vue Router
*   **状态管理**: Pinia
*   **UI 组件库**: Element Plus
*   **样式处理**: CSS (未引入 Tailwind)
*   **HTTP 请求**: Axios (当前由环境拦截模拟，不调用真实后端)

## 页面清单

1.  **Dashboard 首页**: 展示核心营运数据和快捷入口。
2.  **工单管理**: 创建、分配、维修更新、结算工单流转。
3.  **配件管理**: 维护基础配件字典库。
4.  **库存管理**: 查看实时库存情况，生成库存入库、出库与盘点记录。
5.  **支付记录**: 汇总工单相关的客户实收金额等 `payment_record` 明细。
6.  **退款记录**: 展示客户 `refund_record` 售后退款明细。
7.  **官方售后结算**: 录入、审核并确认品牌官方售后结算收入记录。
8.  **报销台账**: 门店费用的申请记录，只有已确认(CONFIRMED)的报销才计入运营成本。
9.  **财务报表**: 多维度统计客户支付收入、官方结算收入、成本和利润结果。
10. **字典配置**: 配置业务涉及的状态枚举值。
11. **用户与权限**: 按角色关联的模拟权限数据、用户、门店绑定关系。
12. **Excel 导出中心**: 集中展示数据报表下载出口入口。

## 当前 Mock 边界

当前版本仅提供前端 Mock UI 环境。以下功能边界 **明确未实现**：

1.  **后端与数据库**: 不接真实后端接口，未设计真实数据库结构，未修改后端项目代码。
2.  **认证与权限**: 未实现真实登录认证与 JWT 令牌拦截，未实现系统真实的菜单级与数据行级 Router Guards 权限限制。
3.  **真实文件导出**: 未引入 xlsx / file-saver 等依赖，没有真实业务 Excel / CSV 文件生成，不触发浏览器真实文件下载动作。
4.  **真实财务规则**: 工单结算不执行真实后端金额校验，不真实累计报销成本和计算企业纯利润，库存调整不真实冻结或扣减资产。

## 目录结构说明

```
.
├── src/
│   ├── api/          # Mock API 函数：用于统一管理异步请求及延迟逻辑（目前未请求真实后端）
│   ├── components/   # 公共组件：例如 MoneyText, PageContainer, StatusTag 包
│   ├── layouts/      # 布局组件：包含顶部 Header 和左侧 Sidebar (BasicLayout)
│   ├── mock/         # Mock 数据存放目录：包含模拟的数据源和枚举
│   ├── router/       # Vue Router 路由配置表
│   ├── stores/       # Pinia 全局状态管理
│   ├── styles/       # 全局基础样式、覆盖 Element Plus 等特定样式
│   ├── types/        # TS 全局接口定义 (如：finance, dictionary 等)
│   ├── utils/        # Axios 实例配置及其它工具函数
│   ├── views/        # 各个核心业务功能对应的页面组件 (按领域驱动原则划分子目录)
│   └── main.ts       # Vue 入口文件
├── index.html        # Vite 项目基础首页
├── package.json      # 项目依赖与开发命令配置
└── vite.config.ts    # Vite 构建打包相关配置项
```

## 后续接后端接口建议

当前 `src/api` 下的函数全部采用 Promise delay 延时并直接返回 `src/mock` 的模拟数据供页面调用。**接口签名仅为前端展示推演，并未固化**。

在进入前后端真实对接时，建议流程：

1.  要求后端根据 `Controller` 或 `API Gateway` 设计产出相应的 API 规范文档或 Swagger 定义。
2.  在前端只需针对 `src/api/` 的文件统一替换为 `axios.get/post` 的真实 HTTP 调用。
3.  `src/types` 仅作为前端 mock 阶段参考，真实接口字段以后端 Controller / DTO / API 文档为准。
4.  未来对接真实后端时，应优先以后端窗口输出的 Controller、DTO、接口路径、状态码、分页结构和错误响应格式为准。
5.  前端尽量通过替换 `src/api` 内部实现完成对接，避免大范围重写页面。
6.  确保真实登录和 JWT 完成闭环后，再将静态 Router 转为具备真实 Guards 判断的数据驱动模式。
